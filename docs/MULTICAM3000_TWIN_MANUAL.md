# MultiCam 3000 CNC 라우터 트윈 사용 매뉴얼

작성일 2026-11-17 · 브랜치 `multicam3000-twin` · 적용 대상 `/v2` 디지털 트윈

MultiCam 3000 Series CNC 라우터(기준 모델 3-204R, 작업 영역 1524 × 3099 mm)를 공장 디지털 트윈에 넣고, PLC나 아두이노 신호로 움직이게 만든 기능을 정리했습니다.

## 2. 실행 방법

```bash
npm run dev
```

브라우저에서 `http://localhost:8089/v2`를 엽니다.

PLC·아두이노 웹소켓 브리지를 붙일 때는 주소 뒤에 브리지 주소를 붙입니다.

```
http://localhost:8089/v2?cncws=ws://브리지주소:포트
```

상세 뷰어는 three.js r128을 인터넷(CDN)에서 받습니다. 인터넷이 없으면 뷰어 패널은 비어 있지만, 공장 모델은 신호를 받아 계속 움직입니다.

## 3. 화면 구성

### 3.1 공장 안의 MultiCam 3000

- 이름 `MultiCam_3000_01`, 위치 (7400, 13300, 0) mm로 기본 배치에 들어 있습니다. 3축 라우터 왼쪽에 있으며, 위치는 가정값입니다.
- 다른 에셋처럼 선택, 이동, 회전, 복제, 삭제할 수 있습니다. 콘텐츠 드로어의 CNC 분류에 **MultiCam 3000 CNC 라우터 (3-204R)** 카드가 있어 다시 끌어다 놓을 수 있습니다.
- 신호에 따라 움직이는 부분:

| 부분 | 따라가는 신호 | 동작 |
|---|---|---|
| 갠트리 | `x` | 길이 방향 이동 |
| 캐리지 | `y` | 갠트리 빔 위 좌우 이동 |
| Z 슬라이드·스핀들 | `z` | 위아래 이동 |
| 공구 | `tool`, `rpm` | 스핀들에 물린 공구 표시, 회전수에 비례해 회전. 랙에서 해당 번호 자리가 비워짐 |
| 집진 후드 | `hood` | 내림 / 130 mm 올림 |
| 로케이터 핀 | `pins` | 올림 / 내림 |
| 진공 구역 (4구역) | `vac` | 켜지면 초록색으로 진하게 표시 |

### 3.2 MultiCam 3000 패널 (상세 뷰어)

화면 왼쪽 아래 **🪚 MultiCam 3000** 버튼으로 엽니다.

- 머리줄: 지금 기계를 움직이는 출처를 보여 줍니다.
  - `시연: (단계 이름)`: 뷰어의 자동 시연대로 움직이는 중
  - `외부 신호 (PLC)`: 최근 3초 안에 신호를 받음
  - 웹소켓을 쓰면 `웹소켓 연결됨 / 연결 중 / 끊김, 재연결 대기`가 함께 나옵니다.
- **위치** 버튼: 공장 화면의 카메라를 MultiCam 3000으로 옮깁니다.
- **✕** 버튼: 패널을 닫습니다. 닫아도 시연과 신호 반영은 계속됩니다.

## 4. 상세 뷰어 기능

| 항목 | 선택지 | 설명 |
|---|---|---|
| 스핀들 | 콜릿 7.5 HP·24k / ATC 5.5 HP·18k / ATC 13.3 HP·32k | 모델과 시연 사이클이 함께 바뀜 |
| 공구 교환 | 리니어 랙 8개 / 로터리 터렛 12개 | ATC 스핀들일 때만 선택 가능 |
| 진공 구역 | 1 / 2 / 4구역 | 테이블 위 구역 표시 |
| 프로그램 | 가공 사이클 / 스핀들 워밍업 | 워밍업은 6,000·12,000·18,000 RPM 단계 |
| 운전 | 자동 시연 / 수동 조그 | 시연은 재생·일시정지·시간 막대·단계 칩으로 이동. 조그는 X·Y·Z 슬라이더와 스핀들·진공·핀·후드·척 버튼 |
| 시점 | 입체 / 정면 / 측면 / 위 | 카메라 이동 |
| 보기 | 선택한 부품만 / 텍스처 / 분해 슬라이더 | 부품을 눌러 역할·작동 원리·사양·연결할 신호·확인할 것을 봄 |

화면 위쪽 램프는 `VAC_ON`, `PIN_UP`, `SP_RUN`, `HOOD_DN`, `CHUCK_OPEN`, `X_MOVE`, `Y_MOVE`, `Z_MOVE` 상태를 보여 줍니다.

가공 사이클(ATC 기준) 순서: 소재 로딩 → 진공 켜고 핀 내림 → T1 장착 → 공구 길이 측정 → 포켓 절삭 → 공구 교환(T1 반납, T2 장착, 길이 측정) → 윤곽 절삭 → 공구 반납 → 원점 복귀, 진공 끔. 콜릿 스핀들은 공구 교환 대신 수동 교환과 Set Surface를 합니다.

## 5. 신호 연결

### 5.1 신호 키

| 키 | PLC 태그 예 | 형식 | 범위·의미 |
|---|---|---|---|
| `x` | `X_POS` | REAL mm | -200 ~ 2900 (음수는 공구 랙 구역) |
| `y` | `Y_POS` | REAL mm | 0 ~ 1440 |
| `z` | `Z_POS` | REAL mm | -100 ~ 0 (0이 맨 위) |
| `rpm` | `SP_RPM` / `SP_RUN` | REAL rpm | 0 이상 |
| `vac` | `VAC_ON` | BOOL | 진공 켜짐 |
| `pins` | `PIN_UP` | BOOL | true = 핀 올림 |
| `hood` | `HOOD_DN` | BOOL | **true = 후드 내림** |
| `chuck` | `CHUCK_OPEN` | BOOL | 척 열림 (램프만) |
| `tool` | `TOOL_NO` | INT | 0 ~ 12, 0 = 공구 없음 |
| `atcPos` | `ATC_POS` | REAL | 로터리 터렛 포켓 번호 (뷰어에만 반영) |
| `atcAdv` | `ATC_ADV` | BOOL | 로터리 터렛 전진 (뷰어에만 반영) |

범위를 넘는 값은 범위 끝으로 잘립니다. 한 번에 일부 키만 보내도 됩니다. 보내지 않은 키는 이전 값을 유지합니다.

### 5.2 연결 방법 세 가지

**① 같은 페이지에서 직접 호출**

```js
window.cnc.set({ x: 1200, y: 700, z: -30, rpm: 18000, vac: true, pins: false, hood: true, tool: 2 });
```

**② postMessage** (트윈을 iframe으로 넣은 부모 페이지나 다른 창에서)

```js
twinWindow.postMessage({ type: 'cnc', signals: { x: 1200, y: 600, z: -40, rpm: 18000 } }, '*');
```

**③ 웹소켓** (PLC·아두이노 브리지)

트윈을 `?cncws=ws://호스트:포트`로 엽니다. 브리지는 메시지마다 신호 키를 담은 JSON 하나를 보냅니다.

```json
{"x": 2000, "y": 1000, "z": -40, "rpm": 18000, "vac": true, "pins": false, "hood": true, "tool": 3}
```

연결이 끊기면 3초마다 다시 연결합니다.

### 5.3 그 밖의 호출

```js
window.cnc.config({ sp: 'atc133', atc: 'rotary', zones: 2, prog: 'cycle' }); // 뷰어 구성 변경
window.cnc.state();                                                       // 현재 상태 읽기
```

`state()`가 돌려주는 값은 뷰어 내부 형식입니다. `hood`는 1 = 올림, 0 = 내림이고 `pins`는 1 = 올림입니다. 보낼 때의 `hood: true`(내림)와 뜻이 반대이니 주의하세요.

### 5.4 신호 흐름

```
PLC / 아두이노 ─ 웹소켓 ─┐
부모 페이지 ── postMessage ─┼─▶ 트윈 window.cnc.set ─▶ 상세 뷰어 (상태의 기준)
같은 페이지 ── 직접 호출 ──┘                                 │
                                                   매 프레임 state()
                                                             ▼
                                                    공장 안 MultiCam 모델
```

- 신호가 한 번 들어오면 상세 뷰어가 수동 모드로 바뀌고, 이후 시연은 저절로 다시 시작하지 않습니다. 시연으로 돌아가려면 패널에서 **자동 시연**을 누릅니다.
- 상세 뷰어를 불러오지 못하면 트윈이 받은 신호를 직접 공장 모델에 반영합니다.

## 6. 확인한 것과 한계

### 6.1 확인한 것 (2026-11-17, 로컬 서버)

- 공장 기본 배치에 모델이 나타나고 갠트리·캐리지·Z축이 따로 움직임
- 웹소켓(가짜 PLC 브리지), postMessage, `window.cnc.set` 세 경로 모두 공장 모델과 상세 뷰어에 같은 값이 반영됨
- 시연 단계가 진행되며 공장 모델이 따라감
- `npm test` 113개 중 112개 통과. 실패한 `telemetry_ws` 1개는 이 변경 전에도 똑같이 실패함

### 6.2 한계

- 시연 속도는 백그라운드 브라우저 패널(초당 1~2프레임)에서만 봤습니다. 일반 브라우저에서 매끄럽게 도는지는 따로 확인이 필요합니다.
- 공장 모델은 ATC 5.5 HP 스핀들과 리니어 랙 8개로 고정입니다. 패널에서 스핀들이나 공구 교환 방식을 바꿔도 뷰어에만 반영됩니다.
- 절삭선(가공 자국)은 상세 뷰어에만 그려지고 공장 모델에는 없습니다.
- `atcPos`, `atcAdv`(로터리 터렛)는 뷰어에만 반영됩니다.
- 트윈의 실시간 텔레메트리(`/ws`, `/api/telemetry`)에는 MultiCam 값이 아직 들어가지 않습니다.
- 부품 형상과 치수, 공구 랙 높이, 캘리브레이션 블록 위치, 핀 위치, 공구 목록, 가공 프로그램은 사진과 자료로 추정한 값입니다.

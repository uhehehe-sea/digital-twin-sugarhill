# 공구 교환(Tool Change) 설계안 — 구현 보류, 공구 정보 대기

작성 2026-11-09. **제안만 담았습니다. 코드는 바꾸지 않았습니다.** 실제 형식은 사용자가 공구 슬롯·T번호·컨트롤러 정보를 준 뒤 확정합니다.

## 1. 현재 상태 (코드 확인 결과)

- `viewer/lib/nc_program.js`의 공구는 **1개**(`DEFAULT_TOOL = { dia: 6, rpm: 18000, feed: 3000, plunge: 600, stepDown: 4 }`, 주석 `// assumed`)입니다.
- Fanuc형 머리말이 공구 교환을 **한 번만** 냅니다: `G21 G90 G17 G40 G49 G80` → `G54` → `T1 M06` → `S18000 M03`.
  - `G49`(길이 보정 취소) 후 **`G43 H1`이 없습니다** → 실제 기계에서는 공구 길이 보정 없이 Z가 움직입니다. 공구 정보를 받으면 반드시 추가해야 합니다.
- 가공 순서: ① 모든 부품의 구멍(안쪽 먼저) → ② 모든 부품의 외곽(반경 보정 + 고정 탭).
- 공구보다 작은 구멍은 경고 후 **생략**(`hole is not larger than the tool — skipped`).
- 재생(`NcProgram.load` → `timing`)은 공구 교환 시간을 넣지 않습니다.

## 2. 공구 테이블 자료구조 (제안)

```js
// tool_table.json (또는 parts_library.json 옆)
{
  "controller": "fanuc",          // 사용자 확인 필요: Fanuc / Syntec / Biesse / Homag / Mach3 …
  "lengthComp": true,              // G43 H 사용 여부
  "changeTimeS": 8,                // 공구 교환 1회 시간 (가정값, 표기 필요)
  "tools": [
    { "t": 1, "pocket": 1, "name": "Ø6 2날 평엔드밀 (외곽)", "dia": 6, "flutes": 2, "type": "flat",
      "use": ["outline"], "lengthMm": 60, "h": 1,
      "byMaterial": { "PP": { "rpm": 18000, "feed": 3000, "plunge": 600, "stepDown": 4 },
                      "PP-GF30": { "rpm": 16000, "feed": 2000, "plunge": 400, "stepDown": 3 } } },
    { "t": 2, "pocket": 2, "name": "Ø3 평엔드밀 (작은 구멍)", "dia": 3, "type": "flat", "use": ["hole"], "h": 2,
      "byMaterial": { "PP": { "rpm": 20000, "feed": 1200, "plunge": 300, "stepDown": 1.5 } } }
  ]
}
```

필드 `use`: `hole`(구멍), `outline`(외곽), `finish`(마무리), `pocket`(포켓), `drill`(드릴 사이클) 등.

## 3. 생성기 변경 방향

1. **작업 → 공구 배정**: 구멍마다 `dia > 공구 Ø + 0.1`인 `hole` 공구 중 가장 큰 것, 외곽은 `outline` 공구. 맞는 공구가 없을 때만 지금처럼 경고 후 생략.
2. **교환 횟수 최소화**: 공구별로 작업을 묶습니다. 순서는 "작은 공구 → 큰 공구"가 아니라 **"안쪽 형상 → 외곽"** 원칙을 우선합니다(외곽을 먼저 자르면 부품이 움직임).
   예: T2 구멍(전 부품) → T1 큰 구멍 → T1 외곽. 같은 공구가 연속이면 교환하지 않습니다.
3. **교환 블록**(Fanuc형 참고, 컨트롤러 확인 후 확정):
   ```
   G00 Z50.000        (안전 높이)
   M05
   T02 M06
   G43 H02 Z50.000    (길이 보정)
   S20000 M03
   ```
4. **재생·표시**: 교환마다 `changeTimeS`(가정값, "가정" 표기)를 재생 시간에 더하고, 장비 카드에 현재 공구 `T02 Ø3`를 표시. 텔레메트리에 `tool_number` 추가.
5. **CAMotics 검증 창**: 공구 표에 T번호별 지름·길이를 모두 나열.

## 4. 테스트 계획

- 공구 2개 테이블 → 교환 블록이 정확히 1번(같은 공구 연속 시 0번) 나오는지.
- 작은 구멍이 더 작은 공구로 **가공**되는지(지금은 생략).
- 모든 `T` 뒤에 `G43 H같은번호`가 오는지(`lengthComp: true`일 때).
- 외곽은 해당 부품의 모든 구멍 뒤에 오는지.
- 재생 시간 = 이송 시간 + 교환 횟수 × `changeTimeS`.

## 5. 사용자에게 받을 정보

- [ ] 공구 슬롯(포켓) 수와 T번호 배정
- [ ] 슬롯별 공구 종류·지름·날 수·길이·용도(구멍 / 외곽 / 마무리)
- [ ] 컨트롤러 종류와 공구 교환 명령 형식, 길이 보정(G43 H) 사용 여부, H번호 = T번호인지
- [ ] 공구·재질별 rpm·이송·플런지·절입 권장값 (현재 재질 선택은 PP, PP-GF30만)
- [ ] 공구 교환 1회 소요 시간(대략)
